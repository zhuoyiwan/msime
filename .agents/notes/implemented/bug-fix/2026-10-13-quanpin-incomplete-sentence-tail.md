# Agent Note: 长句末尾未打完的拼音仍生成中文候选

Status: implemented

## Problem

`woxiangqushangk` 只返回“我想去”和“我”，因为全拼及公共词网格合并都要求所有音节完整。纠错后的长句接简拼尾时，也不能组合整句；邻键类型在所有简拼尾重试中被排除。

## Decision

全拼允许完整音节头加一个合法末尾前缀进入句子词网格。末尾跨度只在对应音节数量的词表中查范围，前面完整音节精确匹配，保留词典完整读音；不允许中间任意简拼、不把未知尾巴猜成字。公共合并对末尾补全的路径检查完整 canonical key。完整整段词库候选已存在时省掉重复的前缀词网格。

带未完成尾部的长句，在头部至少 8 字母时保留邻键纠错。短输入继续排除邻键头部重试，保留 `shng` 不被改成 `sun + g` 的保护。乱序、漏字、多字的已有类型、路径预算与手工分隔符边界保持原有规则。尚未完成的全拼候选可以直接选择，但不进入逐字转换编辑。

历史审计：[单段拼音修正](../testing/2026-10-09-pinyin-correction-single-part.md)部分重叠，保留原有分段排名、路径预算及性能意图；本篇增加句子末尾前缀的边界，不推翻它的切分规则。其余匹配涉及九键和笔画，与本次全拼尾部不重叠。

## Alternatives considered

把所有音节都当作前缀能支持任意简拼，但会扩大长句搜索量并改变短输入排序。仅让用户补全最后的 `e` 无需改代码，却不能满足实际连打体验。任意替换错字母或硬编码“我想去上课”能覆盖截图，但无法守住字典读音和可解释纠错边界。

## Consequences

长句在最后一个字只打声母时仍能生成完整中文候选。新增查询有限制、有缓存和完整读音，选词学习使用 canonical key；候选不保证每个错拼都能猜对。部分输入新增词网格计算，现有整段词库回答优先，避免常见短词重复生成。

截图用例先在旧实现复现失败；修复后与 `sahng`、`shabg`、`shanng`、`shng` 的长句加末尾 `k` 回归通过。全量 Windows Rust 测试暴露已有平台文件映射与分配预算问题，不能以原生包编译代替测试通过。

真实出货词库曾把 `shanngk` 读成 `sha'nang'ke`，小夹具无法发现。完整纠错成功时仍查询纠错头加未完成尾的替代读法，按较少音节优先解最多三种读法，各只插一条首选；宿主开启整句备选也遵守此限制，避免把正确句子挤出默认六条。当前 release 真实词库回归中目标在第 2 条。多错整串由[原字母联合解码](2026-10-13-multi-error-sentence-decoding.md)补充；长度不足 8 的空查询不做字面前缀兜底，保留短输入、模糊音关闭和 14 键切分原语义。

设备选词暴露另一缺口：纠错后的切分把 `shanngk` 缩短，整句候选出现但选中后留下 `k`。末尾补全的生成行改为携带原串作为消费范围，完整词典读音仍在 canonical key。回归同时检查读音与原始输入覆盖；只断言候选文字不足以证明选词成功。
