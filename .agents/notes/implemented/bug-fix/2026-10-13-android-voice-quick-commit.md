# Agent Note: 安卓语音直接上屏与停止贡献上传

Status: implemented

## Problem

识别文字已可见但还要等很久才能输入。识别与联网润色串行执行，润色读取超时达 60 秒；最终插入前又连续三次同步查询编辑器位置。原版贡献开关和上报方法也不符合本机改版需求。

## Decision

Android 本地 `platform.android.voice_quick_commit` 默认开启，语音页提供“快速上屏”。键盘与 Activity 入口均在此模式跳过润色，最终结果直接提交；关闭时保留已配置的润色服务。中间结果只作预览，不永久上屏，不在用户继续编辑后异步覆盖文字。1.2 秒完成提示仅影响面板消失，不作为插入等待。

语音位置快照在 API 31 及以上通过一次 getSurroundingText，旧系统通过一次 getExtractedText 读取。对连接、修订和上下文继续比较；查询不可用时保留结果交由用户插入，避免写入错误位置。系统语言 auto 转设备语言，普通话、英语、粤语使用规范 BCP-47 标签；创建、启动及空结果的错误明确展示。

语音贡献页面入口及生产调用删除，贡献 API 排除在 Gradle 包外，遥测入口在本机模式关闭。系统识别服务自己的联网行为由系统提供者决定；主动选择第三方识别仍须向该服务发送音频，不能把“无训练上传”写成“完全离线”。

历史审计：[系统语音留在键区](2026-10-08-android-platform-voice-in-keyboard.md)部分重叠，保留麦克风与错误处理边界；本篇替代默认等待润色的行为。[识别服务设置](../feature/2026-10-12-android-voice-provider-settings.md)部分重叠，沿用凭据存储及服务选择。

## Alternatives considered

缩短提示消失时间改动很小，但不能缩短 commit 前等待。先插原文再自动替换润色结果能同时得到两者，但用户编辑和焦点切换时容易改错文字。把识别中间结果当作最终文本能更快，却会产生重复提交和丢掉系统后续修正，因此只提交 final。

## Consequences

默认语音不受联网润色等待影响，保留明确选择等待润色的入口。系统从 partial 到 final 的耗时仍由系统服务决定，不能保证真实识别端到端在一秒内。设备测试使用合成 RecognitionService 检查 final 到真实输入框、只插一次及语言接线，不代表真实设备 ASR 准确率。
