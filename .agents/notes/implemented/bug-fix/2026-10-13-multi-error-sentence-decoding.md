# Agent Note: 多处错拼按原字母位置联合解码整句

Status: implemented

## Problem

`wixbwozhdiwnxbyak` 没有完整切分；旧 k-best 只接收至少三字母的静态错拼键，且最多三条纠错边。只提供 `w` 的“我”候选无法满足完整候选需求。目标原文未知，不能以硬编码目标作为验收。

## Decision

只在长输入无法形成普通完整候选时，按原始字母位置建立有界的词图。每条边必须消费非空原文、对应真实词库完整读音；短片段与多处编辑由加权编辑距离覆盖。词图共用既有二元、三元及个人语言模型，输出多个完整可选句子。原拼音仍保留，候选选择才提交。

历史审计：[末尾补全](../../implemented/bug-fix/2026-10-13-quanpin-incomplete-sentence-tail.md)部分重叠，保留末尾前缀及短输入规则；本篇增加无法完整切分时的联合解码。单段纠错测试笔记保留正常输入的预算，本篇不提高旧 k-best 上限。

## Alternatives considered

增加 k-best 和最大纠错数改动少，但仍先按编辑成本丢弃没有词频支持的路径，且两字母错误不在静态表。只保留最长字面前缀能避免吞尾，但没有整句。宿主调用在线 AI 能猜更广的语义，但引入联网与按键延迟，不符合本机边界。

## Consequences

真实词库测试覆盖五种长句尾部和三个已知多错串，目标句在默认前六条；未知多错串出现多个消费整串的中文候选，保留完整 canonical key。输入限制为 8–48 字母，每位置最多 16 个编辑音节边并保留字面边；先保留每个消费长度的最佳边，避免较昂贵的漏字读法完全被短切分挤出。最多 512 个多音节词库键，三音节跨度，beam 24；同串缓存复用，短输入不进入此搜索。

归一量至少取已查询单字频数总和，避免原固定切分的 1e6 常量导致更多拆字得分更高。已有句子只插入两个新结果，保留尾部替代读法在第一页。release 本机测试五种尾部冷查询约 14–70 ms，未知多错约 36 ms，缓存约 0.19 ms；此测量不是手机耗时保证。全量 Windows Rust 当前 1785 通过、16 失败；同工具链原 HEAD 基线 1779 通过、18 失败，当前失败均属于基线，不添加 known-failures 豁免。

## Risks

无法保证高噪声输入的原意，候选可能不自然，必须只作为可选候选。任意切分会增加延迟与过分拆字，需要用真实词库测量并控制。
