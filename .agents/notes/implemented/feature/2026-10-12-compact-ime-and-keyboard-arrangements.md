# Agent Note: 横屏小窗保留候选与可选数字符号排列

Status: implemented

## Problem

用户在横屏游戏中使用 QQ 小窗时，输入法过高，拼音和候选栏不可见，回车仍能上屏文字。代码只限制较大的高度增量，没有对整副键盘按可测量窗口高度封顶，固定高度的键区可能挤出顶部候选。26 键的数字页在改版中固定为电话式，缺少可选排布。

## Decision

键盘竖向列测量时使用实际父窗口约束与当前配置高度，横屏保留部分应用空间；超高时先保留读音、候选与导航区域，只按比例压缩带高度角色的键区。不改变用户保存的高度，旋转回竖屏恢复。沿用 PanelSurface 对覆盖面板的定高测量。

数字页提供电话式、聊天常用、计算器式、数字横排及自定义数字顺序；符号页允许编辑两行常用字符。选择与自定义数据使用本地设置，界面预览当前排布，实时设置重载后重新构建符号页。保留拼音字母映射和功能键，避免布局选项误改输入方案。

## Alternatives considered

只改横屏固定键高最容易，但 QQ 小窗、分屏和字体缩放提供的高度不同，仍可能裁掉候选。统一缩放整副键盘能保持比例，但会使候选字和导航区域也变小。用实际测量预算压缩键区可保留选词区域。

只提供完整拖拽键盘自由编辑可以满足所有习惯，但涉及字母映射、功能键缺失及多语言方案，验证面过大。先提供数字预设和有边界的数字、符号自定义，功能键位置与拼音映射仍受产品约束。

## Verification

横屏及受限窗口中拼音与候选可见、可选上屏，最大保存高度也不覆盖整屏，竖屏还原；预设能切换并持久化，数字无重复遗漏，自定义符号显示与实际插入一致，非法自定义不允许保存。模拟器验证旋转、受限窗口与数字符号输入。

## Consequences

QQ 与厂商游戏小窗的真实窗口实现需真机复测，模拟器只覆盖标准横屏和受限窗口。极小窗口的键帽会变小，候选区域优先。自定义只影响数字和常用符号，不支持任意字母、功能键拖拽。

API 35 在 1080×1920 与 720×1280（320 dpi）模拟器上通过 CompactPrefixDeviceSmoke：最大高度横屏候选可点选上屏、收起重开与恢复竖屏、五种数字方案及自定义符号实际插入。纯 JVM CompactKeyboardPolicySmoke 验证 PanelSurface 再次 EXACTLY 测量不重复缩小；KeyboardArrangementPolicySmoke 验证数字无遗漏及非法自定义。实测发现并修复 CHOICE 设置误用 text() 读取导致数字页进程崩溃，设置页及键区都用 choice()。
