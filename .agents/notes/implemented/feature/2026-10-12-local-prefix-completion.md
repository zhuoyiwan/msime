# Agent Note: 本机手动词条的前缀补全

Status: implemented

## Problem

用户要求姓名、手机号、身份证号输入开头后点击候选补全。常用语已有存储与管理，但没有接入输入中的前缀候选；Windows 快捷短语只在 K 模式支持前缀，普通混输为精确编码。

## Decision

安卓复用 CommonPhrases 本机正文，独立本地设置保存可选字母缩写。仅查询手动保存的一行词条，不自动采集通讯录或学习号码。数字最少三位，匹配正文或缩写。候选点击重新核对连接、选区和前缀；原样数字已在编辑器时仅替换那段，组字时取消引擎组合后插入全文。密码、隐私及禁个性化学习输入框不显示。

Windows 复用快捷短语存储与候选，扩展字母前缀与数字编码；数字起头的预判由版本化 IPC 同步允许起头的数字，数字组字保留原样首选，仅点击补全才输出完整号码。

## Alternatives considered

新建全文词库可以完全隔离管理，但双份正文会让常用语修改与补全不一致。复用已有正文与管理，仅保存别名，避免维护两份数据。自动学习可减少录入，但用户未选择此方式，不将号码自动落盘。

## Verification

合成姓名、号码与身份证词条按前缀匹配，点击后不重复前缀；光标变化和密码框不补全。数字原样输入可用，删除与用户词条管理持久化。两端构建、针对性测试与安卓设备验收通过。

## Consequences

应用可以拒绝读取上文，该情况下无补全；前缀规则不覆盖整个句子的模糊检索。词条不会经局域网剪贴板自动同步，需要分别录入。

API 35 两种屏幕尺寸通过号码、身份证末 X、姓名缩写点击全文、下一次拼音无残留及密码框不显示补全的设备测试。PrefixCompletionPolicySmoke 验证前缀边界、最短数字长度及去重。Windows Server、双架构 TSF 全套 ctest 及设置页 144 项测试通过，数字编码管理、前缀查询和首位掩码另有合成数据回归。Windows 沿用已有快捷短语混入开关，关闭时不接管数字起头；数字模式禁止云候选，IPC 只传十位数字起头掩码，不传正文，配置改变、词条变动和输入方案切换刷新，断线清空。

Android 9（API 28）实际点选手机号补全成功；跨编辑器重建和旋转的批量套件未完整通过，存在旧无障碍节点及冷启动时先直接输入的现象，不能把它记作 Android 9 的完整验收。完整行为验收目前来自 API 35。
